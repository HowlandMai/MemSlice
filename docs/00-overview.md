# MemSlice 设计方案

> 定位：**学习项目**。目标是理解内存分配器的设计与权衡，并展示「如何证明一个
> 系统级组件是正确的」。
>
> 非目标：不追求生产可用、不追求性能超越 glibc malloc、不追求 API 完备。

## 1. 为什么要有这个项目

内存分配器是经典的"轮子"——glibc/jemalloc/mimalloc 已经做得很好，重造一个
通用分配器没有实际价值。但**作为学习载体它有独特的价值**：

1. 分配器处在「数据结构 + 并发 + 系统调用 + 内存布局」的交叉点上，一个项目
   能覆盖多个主题
2. 它的正确性可以被**严格验证**（不变量可枚举），适合练习"如何证明代码是对的"
3. 它的性能可以被**量化归因**（指令级、缓存行为），适合练习"如何用数据说话"

本项目刻意选择**小而完整**，而不是大而浅。

## 2. 核心设计（保留的精髓）

### 2.1 两级分配器

```
请求 size
   │
   ├─ size <= kMaxSmallBytes ──> 二级分配器（空闲链表，按对齐后尺寸分桶）
   │                                 │
   │                                 └─ 桶空时向系统批量申请 chunk，切分成块
   │
   └─ size >  kMaxSmallBytes ──> 一级分配器（直接 malloc/free）
```

**为什么分两级**：小对象按固定尺寸分桶可以 O(1) 复用、避免每次 malloc 的
系统调用与元数据开销；大对象分桶则浪费严重（一个 4KB 请求占一整个桶不划算），
直接交给 malloc 更合适。

### 2.2 自描述头部（可回收的关键）

每个分配出去的块，在用户指针**前面**放一个小头部：

```
   raw（块起始）
    │
    ├─ [头部: base | packed]     ← 记录真实基址与「容量 | 来源 | 状态 | 魔数」
    ├─ （对齐填充）
    └─ 用户指针 p                ← 返回给调用方
```

**为什么需要**：`free(p)` 只有指针、没有尺寸。头部让释放无需调用方提供尺寸，
且能区分"这块是小对象块还是 malloc 块"，从而路由到正确的回收路径。

### 2.3 空闲链表节点复用块本身

空闲块的**前 8 字节**存放 `next` 指针，不额外分配节点：

```
   空闲时: [next | ......... 未使用 ......... ]
   分配后: [头部: base | packed | 用户数据...  ]
```

**这是本项目最值得注意的细节**（也是 MemSlice 踩过坑的地方）：`next` 与头部
**占用同一段内存**。因此：

> **不变量：一个块不可能同时处于「空闲链表态」和「已分配态」。**
> 任何在把块挂回链表之后还去读写头部的代码，都会读到链表指针——这是真实的
> bug 来源（详见 docs/03-building-log.md）。

### 2.4 并发策略（清晰的取舍，不是"全都有"）

采用**分桶加锁**：每个尺寸桶一把锁。

- 优点：不同尺寸的分配/释放互不阻塞；实现简单、正确性容易论证
- 缺点：单线程下每次操作都要加解锁，实测比无锁慢约 3 倍
- **诚实记录**：这是刻意的取舍。真正的解法是 thread-local 缓存，但那引入
  跨线程归还的所有权问题，本项目不实现（见 docs/04-performance-notes.md）

## 3. 可验证性（本项目的差异化亮点）

绝大多数内存池作业**没有验证**。本项目把"如何证明实现是对的"当作一等公民：

| 机制 | 作用 |
| --- | --- |
| **不变量审计 `audit()`** | 只读检查池内部账目：链表无环、节点归属本池、桶与容量一致、块唯一性 |
| **注入错误测试** | 故意造出坏链表（成环/错位），证明审计**真的能抓到**——否则审计是装饰 |
| **随机长跑** | 固定种子的随机 alloc/free/realloc 序列，每步校验数据完整性与账目 |
| **指针唯一性** | 全部存活时校验地址两两不重叠（能抓"同一块交出两次"） |
| **CI 门禁** | 一条命令跑齐：用例 + ASan/UBSan + TSan + valgrind + 零告警 + 格式 |

**核心观点**：一个"能自己抓错"的池，比一个"看起来能跑"的池有说服力得多。

## 5. 与原版实现的关系（诚实声明）

核心算法（两级分配器 + 空闲链表 + 边界标记）来自经典设计，**与 SGI STL 的
`__default_alloc_template` 思路一致**。本项目不假装算法原创，差异在于：

1. **自描述头部**：原版 `free(p)` 需要调用方传尺寸（或按桶反推）；本项目用头部
   让 `free(p)` 单参、且能区分来源
2. **现代 C++ 表达**：`constexpr` 推导、模板配置、`if constexpr` 零开销开关
3. **可验证性体系**：不变量审计 + 注入错误测试（原版没有这层）
4. **诚实的性能边界**：明确标注"打不过 glibc malloc"，并给出归因

> 面试时能讲的不是"我发明了分配算法"，而是"我理解它的每个权衡，并且能证明
> 我的实现是对的、知道它的边界在哪"。后者更稀缺。

## 6. 规模控制

- 核心实现：约 500 行（含注释）
- 测试：约 780 行
- 文档：约 2500 行（本项目文档占比刻意高于代码）

**刻意不做的事**：线程本地缓存、内存整理/合并、可配置分配策略、
mmap 直连、超对齐的复杂处理。它们会让代码膨胀，但不增加核心理解。
